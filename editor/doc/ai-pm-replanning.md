# AI-PM 重规划与变更影响

2026-11-06，第 4 批。沿用当前 Canvas、AI-PM 详情、项目总览待办及引擎原生控件，不新增布局或主题。

## 从规划到人工决定

- 首次规划仍生成待确认 TaskCard。后续规划生成 AI-PM 详情里的逐项变更，区分新增、修改/后续修订、显式撤销与无变化保留。没有出现在回复里的旧任务保持不变，人工改稿不会被新回复直接替代。
- 使用 `existing-task-id` 明确关联已有任务；保留 `plan-task-id` 表达任务沿袭。依赖既可以引用本次规划短 ID，也可以引用现有完整 TaskCard ID；不接受未知、循环或重复匹配。
- 每项列出名称、职员、阶段、规格、目录、交付和依赖的前后差异，并展示队列、产出版本及批准情况、下游依赖和原工作入口。项目总览的既有“待我处理”列出重规划待审项。
- 人工逐项确认或拒绝。拒绝某项保留原工作，不撤销其他项的决定。依赖尚未确认的新修订时不能确认下游；拒绝前置后需重新规划该依赖，不能静默退回旧版本。
- 未处理完当前变更前不能继续生成下一轮规划，避免覆盖尚未审核的提案。

## 执行与交接

1. 未开始任务可以确认改派、改规格或撤销。确认修改创建稳定身份的后续 Task 和新工作 Canvas，填写 Person、任务规格、交付要求和固定任务依赖；不覆盖原工作文件。
2. 执行中或状态待核对的任务必须先请求停止。项目台账立即阻止该任务的新入队和领取，随后通过本机 Companion 已有 `/api/interrupt` 请求中断对应真实 turn。请求成功不视为已停止；必须得到实际终态，未知状态保持阻塞。
3. 有执行记录时，需要打开原工作与产出核对，填写交接说明。核对绑定执行、文件摘要、成果与批准状态；它们再变化时必须重新核对。
4. 新 Canvas 的 Action 包含人审交接说明、原工作入口及摘要、已有成果身份。旧文件只读保留，旧批准不代表新任务已经完成。正式成果输入继续经过原有准入检查。
5. 原未验收范围被替代或撤销后，未开始的旧队列取消，旧工作不能从其他已打开窗口重新执行。已开始、已结束的执行记录保留。同职员的其他独立任务不会被变更锁卡住。
6. 已验收任务不能撤销或重置。新增范围生成后续修订，保留原验收、批准、成果与历史进度，新任务重新经历产出与验收。

未明确升级的下游任务继续绑定原任务和版本；若原未验收范围被撤销或替代，下游保持阻塞，影响中明确列出，需另行审阅它的依赖变更。

## 持久化与恢复

PM 节点保存 `plan-changes` 和已处理的 `plan-history`，兼容原 v1 Canvas。项目台账追加 `planning-decisions`，记录具体变更内容指纹、人工决定、停止/交接记录、应用状态及生成的工作身份；Task 增加 `planning-hold`、`scope-status`、`previous-task-id` 等增量字段。

应用先在台账事务中核对预览版本并保留变更锁，再生成工作文件，最后提交关联与取消旧待执行队列。新文件在提交完成前不能执行。重复应用复用同一 Task/Canvas，不创建聊天；聊天仍在之后由 Person 正式执行时按现有绑定流程处理。

中途失败保留 `applying` 决定与变更锁。处理报错、必要时重新核对后可重试，不能把已确认的应用当成普通待审项直接拒绝。已有人工文件不覆盖。若台账已经提交而 PM 文档尚未保存，下次打开会按已记录的决定恢复显示。复制规划文件造成身份冲突时明确阻止复用决定；文件移动治理属于后续批次。

这是可恢复的多文件工作流，不是跨台账与文件系统的单次原子操作。停止与交接不会自动回滚真实职员已经写入的游戏文件，管理人员需核对并保留必要产出。

## 验证

隔离领域回归覆盖部分拒绝、保留人工改稿、显式撤销、依赖升级、已验收历史、停止与真实终态核对、交接说明、旧窗口准入、独立任务领取、内容/文件/队列变化、重复应用、文件重开恢复和应用中断恢复。

最终全 AI 源码回归：193 项测试、1515 条断言，0 断言失败、1 个环境错误。错误为既有 `library-path-boundary-test` 在 Windows 上没有创建符号链接的权限，未将该项标为通过。记录为 `tmp/replan-all-final-tests.log`；本批变更的 clj-kondo 检查为 0 错误、0 警告。较早全量运行受已缓存 AOT 类影响，故障注入没有触达动态写入边界；最终运行显式热加载源码后已消除这 6 条误报。

通过独立 REPL 的 `cljfx.plorer` 实际点击了批准与拒绝按钮：前置未批准时下游禁用，批准后可继续审核，拒绝下游保留原工作。界面证据：[逐项审核](images/ai-pm-replan-review.png)、[部分批准与拒绝](images/ai-pm-replan-decided.png)。截图使用隔离样本单独展示现有 PM 详情组件，正式入口仍在原 Canvas 详情区。

测试没有发送真实职员模型请求，也没有对当前项目发起停止或交付验收。本轮是源码与隔离热加载验证，未打包安装或替换正式编辑器。
