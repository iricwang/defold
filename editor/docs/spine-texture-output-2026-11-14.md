# Spine 贴图输出倍率：非破坏性缩放

2026-11-14。已实现并会话热更到本机 Defold。运行时引擎未修改，已安装应用 JAR 未替换。

## 使用流程

1. 打开 `.skeleton`，点击骨骼层级上方工具栏最右侧的图片图标，提示为“贴图分辨率”。
2. 使用 1%～100% 连续滑杆，或输入小数百分比，例如 37.3712。它不是几个固定档位；最终 PNG 尺寸按像素取整，至少为 1×1。
3. 点击“应用到预览与导出”。此时一次性提交文档修改，支持撤销与重做；拖动滑杆只是草稿，不会连续污染撤销栈。
4. 保存 `.skeleton`，通过项目菜单的“导出 Defold”更新游戏资源，再正常构建/打包。倍率改变本身不会自动重写已经导出的游戏资源。

本次采用会话热更供验证，参数可保存和重开；要让新功能在重启已安装应用后继续生效，仍需后续增量安装。本次未打安装包。

## 数据和资源约定

文档新增 `texture-output.scale`，缺省 1.0，合法范围 [0.01, 1.0]，拒绝 NaN、Infinity 和非法值。

作用范围是当前骨架的全部动画共用图片，包括全部皮肤和图片序列帧。多骨架工作区中的其他骨架保持各自设置。该设置属于 Defold `.skeleton` 创作数据，不承诺写入第三方原生 `.spine` 工程格式。

缩小后的图片位于导出目录的 `<骨架名>_textures/<原图片相对路径>`。图集 animation ID 仍对应原 Spine 附件路径，仅更换引用的 PNG；骨骼、路径、网格顶点、UV、权重和动画 JSON 均不缩放。连续缩小时始终从原图生成，避免反复缩放累计损失；恢复 100% 时重新引用原图。旧的派生文件不会被粗暴删除，但没有其他引用和 custom_resources 强制收录时不会进入包体。

采样采用预乘 Alpha、渐进缩小和 Bicubic 插值，编辑器预览与输出 PNG 共用实现。引用图片损坏时预览保留缺图行为，避免停掉编辑器刷新。派生 PNG 使用同目录临时文件替换；整个多文件导出不构成跨文件系统事务，导出失败后需重新导出，不能直接交付残缺输出。

资源列表先显示文件名和原始/输出尺寸，完整路径可横向查看；统计全部唯一 PNG 的 RGBA8 像素量。**这不是打包图集实际占用**，还不含排版留白、边缘扩展、Mip、平台压缩和驱动开销。实际结果以构建纹理为准。

三个倍率均经过真正的 Bob `--variant debug --archive build`，并经 `defold-background` 启动实际引擎、播放到固定时刻并抓取原始 GPU 帧。

Manifest 清单确认包内引用 `Imported_skeleton.texturec`，没有原始 PNG 资源条目。三个导出 `.spinejson` 的 SHA-256 完全相同，实际原图 SHA-256 未变化。画面中角色可见边界变化在 1–2 像素范围内，属于缩小采样造成的边缘变化；骨架和模型空间尺寸保持不变。
