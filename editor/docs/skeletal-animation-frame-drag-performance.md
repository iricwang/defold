# 按帧合并拖动与提交性能 — 2026-11-12

接续[大网格性能第二轮](skeletal-animation-large-mesh-performance.md)。本轮仅修改编辑器 view、render、slot-view 以及测试/性能脚本，运行时引擎不改。

## 实现

- 连续变换输入保留最新事件，在编辑器刷新开始时处理一次。松手同步处理最终坐标，再进入既有提交逻辑；取消后不会恢复旧草稿，整次手势保持一次撤销。平移、变换、网格和姿态操作沿用原有计算逻辑；权重笔刷与骨骼创建保留全部路径事件。
- 动画 FFD 缓存基线数值、选中顶点的影响项和逆变换，反复使用局部 double[] 工作缓冲区。正式文档取得独立的不可变数值向量；不把可变数组放入撤销历史。每类预览缓存上限仍为两项。
- TriangleMesh 每个附件复用 float[] 坐标缓冲区，尺寸不变时只同步最小变化区间；UV 和拓扑继续独立复用。坐标全量合法性检查先于写入，失败不会污染缓冲区。稀疏变化可能合并为一个较大的连续区间；不声称 GPU 后端只处理单个顶点。
- 松手后层级树只在骨骼/插槽父子关系、名称、顺序、约束/动画/皮肤列表或搜索变化时重建。纯坐标与关键帧数值更新保留原 TreeItem。
- 普通动画附件没有序列帧控件时，属性面板直接跳过 setup 附件管理器。原实现即使最终不显示这些控件，也会全量导出 Spine JSON 并创建大段顶点文本。设置模式、实际序列帧附件仍走完整原有控件路径。

本轮没有引入 ReactFX、替换撤销框架或更改游戏运行时。采用了按帧合并与复用数值缓冲的设计。没有修改高级混合/裁剪的 GPU 回读路径。

## 验证

- 源码：430 项、13,590 条断言；最终 AOT 编译版：364 项、12,717 条断言，均 0 失败、0 错误。
- 完整后台交互：134 步通过，JavaFX 正常退出 0，没有原生崩溃。涵盖设置/动画、多选变换、关键帧、撤销/恢复、约束、属性和播放。
- 新增实际输入测试覆盖 50 次移动合并、释放时的新坐标、单次撤销/恢复、取消后清队列、笔刷与创建工具保留每次采样。
- 新增缓冲测试覆盖存储身份复用、最小上传区间、未变化不上传、尺寸变化、无效数值失败恢复、变形快照不被覆盖和选择变化失效。
- 新增结构测试覆盖几何/关键帧不重建结构，新增骨骼和搜索改变会失效。属性测试覆盖尚不可导出的编辑中 UV、无序列动画附件与无效插槽。
- 使用本轮新 FFD 路径在 attack 的 0.35 秒将 05_tail 顶点 0/1/2 平移 [3,2]，导出后与 Spine 官方 4.2.120 对比：8 段动画、617 帧，最大顶点误差 0.0000686904065，小于 0.0001；绘制顺序及附件状态一致。导出 SHA256 为 fd62a3760ae1c96d0f5a2f3bb5115309b76f260b32cf53590b897fda277088ea，区别于未修改夹具。
- 修改行无新增 clj-kondo 告警，34 条既有告警单独保留；Python 入口通过编译检查。
- JAR 差异只涉及三个编辑器命名空间，运行时引擎文件无差异。工作区其他既有修改不在本轮范围内。
