# 大网格拖动性能优化 — 2026-11-12

接续[第一轮性能优化](skeletal-animation-performance.md)。本次基线是上一轮完成后的编辑器，以下提升是进一步优化的结果；运行时引擎没有修改。

## 主要结果

1024 顶点整网格拖动，无贴图中位数 **32.88 → 15.15 ms**（减少 54%），P95 **42.71 → 20.19 ms**；真实贴图中位数 **33.93 → 17.26 ms**（减少 49%），P95 **41.58 → 22.72 ms**。真实贴图单顶点拖动 **35.07 → 16.72 ms**。每次整网格拖动的 FX 线程分配，无贴图 **57.31 → 21.90 MiB**，真实贴图 **62.11 → 26.99 MiB**。

这不是稳定 60 fps 的承诺。P95 仍高于 16.7 ms，测试不测 GPU 最终呈现；05_tail 松手提交仍有约 94–106 ms 停顿，需要继续优化。骨骼拖动等非主要目标项基本持平，不能把网格收益推广到所有操作。

## 测量方法

- 同一 ARM64 macOS 机器，OpenJDK 25，3 GB JVM 堆，JavaFX Metal 后台窗口；安装基线与编译方法一致。
- 05_tail 原案例 + 32×32、1024 顶点、129 根骨骼、每顶点两条权重的压力案例。压力案例分别关闭纹理、开启真实尾巴纹理；贴图版断言图片实际加载成功。它是合成大网格，不是 1024 顶点的生产美术资产。
- 每种工况预热 15 次，拖动/框选 90 次、时间轴 60 次、空闲/悬停/播放 120 次、笔刷 30 次。两版均开 JFR，串行运行，正式测量不同时运行测试或编译。
- 通过 cljfx.plorer 给真实编辑器控件发送按下、拖动、松开事件，覆盖草稿生成、刷新、CSS/layout；记录 FX 线程操作墙钟时间和分配量。笔刷项只测数据计算；不包含显示器呈现延迟。
- 完整最终版结果为 `final3` 和 `final-textured3`。早期省略外层 vector 的候选构建曾引起 GPU buffer 类型错误，已修复并增加实际 UV/face buffer 回归；该失败结果未计入最终表。

## 实现与正确性

1. 缓存重复使用的世界顶点、操纵柄坐标、UV/三角形拓扑和网格连线。每类只保留当前草稿与手势基线两项；文档、附件、姿态、FFD、选择、轴空间、工具和支点变化时失效。
2. 解析后的 Spine JSON 最多缓存四项，以不可变源字符串身份区分，保留原始通道顺序。连续 FFD 草稿共用原源数据，避免每次鼠标移动解析两遍整个 JSON。
3. 时间轴与附件列表的只读查询直接读取已有轨道，不再导出整个网格。首次写入轨道仍保留完整导出和校验；文档边界验证没有跳过。
4. 拖动过程复用已解析的 FFD 轨道，提交到现有变形写入接口；未改权重、插值、变形算法和撤销语义。
5. 特别测试混合/显式 FFD 在骨骼和时间不变时切换，避免控制柄缓存停在旧位置；并验证容量上限、非法数据不入缓存、UV buffer 类型和拓扑变化。

最终源码回归 **418 项 / 13,509 条断言**；最终 AOT 编译版 **352 项 / 12,636 条断言**，均 0 失败、0 错误。后台完整交互 **134 步**通过，JavaFX 正常退出 0；所有性能场景停用处理器和停止计时器均为 0。

Spine 官方 `@esotericsoftware/spine-core` **4.2.120**：05_tail 的 8 段动画、**617 帧**逐帧对照通过，容差 0.0001，最大顶点误差 0.0000686904065；绘制顺序和附件状态无差异，导出 SHA256 与优化前一致。

新修改行 lint 无告警，修改的测试/性能脚本无告警；两个既有生产文件剩余 44 条告警记录在证据中。Python 入口通过编译检查。JAR 审计仅改动编辑器 slots/view 命名空间，无运行时引擎差异。既有工作区其他修改不在本轮范围内。
