# 骨骼与网格编辑器性能回归 — 2026-11-12

已完成当前骨骼、网格与动画编辑流程的性能回归和针对性优化。运行时引擎未改。本报告覆盖编辑器交互路径，不代表 AI Canvas、构建服务、整个游戏运行时或所有机器的性能结论。

## 结果与测量边界

同机 ARM64 macOS 26.7.2，JVM 报告 Macmini9,1、8 核、16 GB；OpenJDK 25.0.4.1，JavaFX Metal 后台窗口，3 GB JVM 堆。比较使用相同安装基线、编译方式和夹具。对照构建恢复本轮修改前的 mesh/view 源码；IO 基线源码与安装 JAR 内源码一致。测量按基线、优化版顺序串行运行，CPU 组均开启 JFR，pulse 组均不开启 JFR。

- 实际案例：05_tail 项目、8 段动画，真实播放加载 11 张贴图。
- 压力案例：32×32＝1024 顶点、129 根骨骼、每顶点两条权重；无贴图，隔离几何与编辑计算开销。
- 每个 CPU 工况预热 15 次；空闲/悬停/播放各 120 次，拖动与框选各 90 次，时间轴 60 次，笔刷 30 次。拖动通过 `cljfx.plorer` 发送真实按下、移动、松开事件，并断言命中画布、产生草稿。
- CPU 表记录 FX 线程操作的墙钟耗时，包含事件处理、刷新和 CSS/layout；不包含 GPU 最终呈现。笔刷项只测笔刷数据计算。时间轴项修改播放时间并走完整刷新。

## 修改内容

1. 姿态、插槽采样和网格边界按不可变对象身份及动画/时间复用。每类只保留当前草稿与手势基线两项，避免保留整段编辑历史；混合动画和显式采样结果绕过单动画缓存。
2. 已验证的导出网格布局最多缓存 32 项。网格对象变化即重新检查；交叉 UV、权重、拓扑的完整导出检查仍保留。
3. 持续拖动时间轴时复用属性控件，在首个静止帧补齐数值；选择、附件和文档变化立即刷新。浮动操作栏只在提示内容变化时创建 Tooltip。
4. 拖动过程中不重复做导出兼容性预检；提交后更新提示。预检直接读取实际保留的插槽和动画双色字段，并校验文档，不再为材质提示导出、序列化和解析全部 FFD 数据。真正导出依然走完整导出与校验流程。
5. 增加独立 CPU/pulse/JFR 压测入口及持久化素材夹具。启动器在隔离窗口测完后请求 JavaFX 正常退出并等待，不立即 SIGTERM；保存退出状态，发现原生崩溃时返回失败。

[JFR 摘要](skeletal-animation-evidence/2026-11-12/performance/jfr-summary.json)显示，优化前大量采样停在网格边界相交检查和导出布局，优化后主要剩下绘制、世界顶点变换、FFD 重映射。采样计数包含预热与提交，不是精确 CPU 百分比。

## 重复运行

在仓库根目录运行。`EDITOR_JAR` 指向需要比较的编辑器包，输出必须为新目录；每次启动都会复制夹具，原游戏工程不被打开或修改。JavaFX 原生后台测试需要本机 GPU 环境，但不要求解锁屏幕或发送桌面输入。

```sh
python3.12 editor/scripts/skeletal_animation_benchmark.py \
  --jar "$EDITOR_JAR" --java /opt/homebrew/opt/openjdk@25/bin/java \
  --backend background \
  --project editor/test/resources/skeletal-animation/performance-project \
  --scenario editor/test/headless/skeletal_animation_performance.edn \
  --fixture-edn editor/docs/skeletal-animation-evidence/2026-11-12/mesh-transform/tail-input.edn \
  --measure cpu --jfr --output /tmp/defold-perf-cpu --scenario-timeout 300
```

播放测试将 `--measure cpu --jfr` 改成 `--measure pulse`，并更换输出目录。两个版本的参数、JFR 开关和机器负载应一致，串行测量，至少复测一次；检查 `performance.json`、`report.json`、`shutdown.json` 后再比较。

完整交互使用同一个启动器 `editor/scripts/headless_editor.py`，场景换成 `editor/test/headless/skeletal_animation_mesh_transform.edn`，省略 `--fixture-edn`、`--measure` 与 `--jfr`。源码测试入口为 `editor.skeletal-animation-performance-test`，与现有 skeletal suites 一起运行。

详细数据、夹具散列、构建范围、测试日志与仅本轮源码差异见[证据目录](skeletal-animation-evidence/2026-11-12/performance)。大体积 JFR 和验证 JAR 留在本机 `/tmp/spine-perf/`，没有作为发布包提交。
