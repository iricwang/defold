# 内置骨骼动画示例

在 Defold 中打开 `puppet.skeleton`，可以编辑五根骨骼、图片附件、加权网格、
双骨骼 IK、变换关键帧与网格变形关键帧。两张 PNG 来自仓库已有测试资源。

在顶部的导出路径输入框中填入 `generated`，然后点击 **Export for Defold**
（中文界面为“导出到项目”），生成 `puppet.go` 使用的 Spine JSON、
Defold 图集、Spine 场景和模型。路径相对于项目目录；重新导出会更新同名资源。

`.skeleton` 是编辑器制作文件，游戏使用导出的资源。运行需要 `game.project`
中配置的 Spine 扩展及包含该扩展的匹配引擎。仅在本地构建；不要将项目源码上传
到远程原生扩展构建服务。

自动回归时使用 `--config=test.enabled=1` 启动已编译的项目。示例验证动画完成、
目标骨骼移动，以及每帧 IK 末端跟随；成功后输出
`SKELETAL_AUTHORING_RUNTIME_OK` 并退出。

## 已验证范围

当前编辑器的 Bob 与 Spine 扩展 4.9.2 已成功编译全部导出资源。本机现有的
Spine 引擎为 Defold 1.13.1、扩展 4.7.4，因此实际运行使用该引擎匹配的官方
Bob 和插件，在独立临时项目中验证相同导出内容。动画完成与 IK 跟随断言通过；
引擎录制的游戏画面也确认了加权网格与变形的显示。

编译后的着色器与引擎版本相关，不能用 1.13 引擎运行 1.14 的构建产物。
正式开发请使用与当前项目版本匹配、包含 Spine 扩展的引擎。本示例验证运行与
几何行为，不声明与专有 Spine 编辑器逐像素一致。

## 编辑流程

1. 在资源面板新建“骨骼动画 / Skeleton Animation”（`.skeleton`），或打开此示例。
2. 使用“导入 Spine”选择 Spine **4.2 JSON**（`.json` / `.spinejson`）。也可直接选择已支持的 Spine 4.2.43 `.spine` 工程，由内置原生编解码器独立读取，无需安装 Spine。多骨架工程会先让你选择编辑对象；未验证的版本或对象会明确报错。目前不支持 `.skel`。PNG 会复制到当前项目的新目录，原始文件不会被覆盖。
3. `setup` 模式建立骨骼、绑定 PNG、调整网格和权重；`animate` 模式编辑局部变换、网格变形或 IK 混合时会记录关键帧。选择网格插槽后使用 `mesh` 工具拖动顶点；权重在 `setup` 模式指定骨骼及 0–1 权重，其他影响会自动归一化。
4. 在摄影表点击或拖动关键帧，使用鼠标中键平移、Ctrl＋滚轮缩放时间轴。选择关键帧后可以选择 Linear、Stepped 或 Bezier；在曲线页拖动 Bezier 控制柄。
5. 层级和属性位于画布右侧，上下分隔线可以调整摄影表／曲线区域高度。保存及撤销／重做使用 Defold 的标准快捷键。
6. 导出到当前项目目录后，在游戏中引用生成的 `.spinemodel`，通过 `spine.play_anim()` 播放。
7. “另存为 .spine”通过内置编解码器创建一个新工程；也可在输出路径框填入新的 `.spine` 文件名后点击按钮。未选中编辑的骨架会保留。编码在后台执行，验证失败不创建目标文件。当前只允许另存新文件，拒绝覆盖已有工程。

## 兼容范围

当前可制作和编辑骨骼变换（包括 X/Y 错切及错切动画）、区域贴图、非加权／加权 Mesh、逐顶点变形、完整 IK 参数、Transform、Path、Physics 约束以及动画曲线。网格工具支持拓扑编辑、自动生成、透明度描摹和重置；权重工具支持自动绑定、笔刷、平滑、锁定、剪枝与镜像。根骨骼不能作为 IK 被约束骨骼；请先增加父骨，以避免 Spine 原生运行时崩溃。

这并非 Spine 全功能的完全替代。附件切换、RGBA/RGB/Alpha 和绘制顺序支持导入预览；这些轨道的完整制作 UI、剪裁、双色染色、特殊混合、序列帧和组合皮肤仍未完成。播放到非当前制作附件时属性栏只读，避免误写原附件。未支持内容会在兼容说明中标出。带序列帧附件的资源导出会明确拒绝，避免生成缺失贴图的包。对存在未支持内容的项目，导出后仍应使用匹配的 Spine 运行时验证。


## 独立原生工程读写

内置编解码器按已验证的 Spine 4.2.43 格式处理工程；产品读写路径不启动本机 Spine。
未知版本、未知对象以及无法安全保留的数据会明确拒绝，不会降级到外部 CLI。
多骨架文件只更新所选骨架，其他骨架保留；另存到其他目录时会重定位图片和音频目录。
验证工具仍可使用已安装的 Spine 作为互操作对照，这不属于应用运行依赖。

完整范围及逐项验收标准见 [功能矩阵](../../docs/skeletal-animation-parity.md)。

皮肤下拉框支持切换和复制皮肤。每次切换先保存当前附件与变形关键帧；缺失的附件回退到 default 皮肤。副本可独立编辑，导出的 `.spinemodel` 使用当前皮肤。组合皮肤和皮肤专属骨骼／约束尚未实现。

仅含 default 附件的工程首次复制皮肤时，会将原始外观转换为 `base` 命名皮肤，保留副本独立的附件名称，确保原生 Spine 能导入。已混用命名皮肤和 default 共享附件的工程，请选择命名皮肤复制；共享 default 的整体迁移尚未支持，会明确拒绝。
