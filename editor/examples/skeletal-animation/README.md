# 内置骨骼动画示例

在 Defold 中打开 `puppet.skeleton`，可以编辑五根骨骼、图片附件、加权网格、
双骨骼 IK、变换关键帧与网格变形关键帧。两张 PNG 来自仓库已有测试资源。

在顶部的导出路径输入框中填入 `generated`，然后点击 **Export for Defold**
（中文界面为“导出到项目”），生成 `puppet.go` 使用的 Spine JSON、
Defold 图集、Spine 场景和模型。路径相对于项目目录；重新导出会更新同名资源。

`.skeleton` 是编辑器制作文件，游戏使用导出的资源。运行需要 `game.project`
中配置的 Spine 扩展及包含该扩展的匹配引擎。仅在本地构建；不要将项目源码上传
到远程原生扩展构建服务。

自动回归时使用 `--config=test.enabled=1` 启动已编译的项目。示例验证动画完成、
目标骨骼移动，以及每帧 IK 末端跟随；成功后输出
`SKELETAL_AUTHORING_RUNTIME_OK` 并退出。

## 已验证范围

当前编辑器的 Bob 与 Spine 扩展 4.9.2 已成功编译全部导出资源。本机现有的
Spine 引擎为 Defold 1.13.1、扩展 4.7.4，因此实际运行使用该引擎匹配的官方
Bob 和插件，在独立临时项目中验证相同导出内容。动画完成与 IK 跟随断言通过；
引擎录制的游戏画面也确认了加权网格与变形的显示。

编译后的着色器与引擎版本相关，不能用 1.13 引擎运行 1.14 的构建产物。
正式开发请使用与当前项目版本匹配、包含 Spine 扩展的引擎。本示例验证运行与
几何行为，不声明与专有 Spine 编辑器逐像素一致。

## 编辑流程

1. 在资源面板新建“骨骼动画 / Skeleton Animation”（`.skeleton`），或打开此示例。
2. 使用“导入 Spine”选择 Spine **4.2 JSON**（`.json` / `.spinejson`）。这是运行时 JSON 交换格式，不直接读取 Spine 的二进制 `.spine` 工程或 `.skel` 文件。PNG 会复制到当前项目的新目录，原始文件不会被覆盖。
3. `setup` 模式建立骨骼、绑定 PNG、调整网格和权重；`animate` 模式编辑局部变换、网格变形或 IK 混合时会记录关键帧。选择网格插槽后使用 `mesh` 工具拖动顶点；权重在 `setup` 模式指定骨骼及 0–1 权重，其他影响会自动归一化。
4. 在摄影表点击或拖动关键帧，使用鼠标中键平移、Ctrl＋滚轮缩放时间轴。选择关键帧后可以选择 Linear、Stepped 或 Bezier；在曲线页拖动 Bezier 控制柄。
5. 层级和属性位于画布右侧，上下分隔线可以调整摄影表／曲线区域高度。保存及撤销／重做使用 Defold 的标准快捷键。
6. 导出到当前项目目录后，在游戏中引用生成的 `.spinemodel`，通过 `spine.play_anim()` 播放。

## 兼容范围

当前可制作和编辑骨骼变换、区域贴图、非加权／加权 Mesh、逐顶点变形、单／双骨骼 IK 以及动画曲线。根骨骼不能作为 IK 被约束骨骼；请先增加父骨，以避免 Spine 原生运行时崩溃。

这并非 Spine 全功能的完全替代。导入的其他皮肤、非活动附件、路径／变换／物理约束、剪裁、绘制顺序和其他未支持轨道会保留原始数据，并在“导入兼容说明”中标明不能编辑或预览的部分。带序列帧附件的资源导出会明确拒绝，避免生成缺失贴图的包。对存在未支持内容的项目，导出后仍应使用匹配的 Spine 运行时验证。
